Files

The file carries DL-TerrainSlicer's six pass layers unchanged, so a laser configuration already set up for that tool can be reused as it stands.

The DXF is for the machine; the SVG is for everything else — a print layout, a report figure, Illustrator. Both carry the same geometry in the passes' own RGB colours. ⚠️ The SVG's stroke width is a hairline for visibility only: on the machine a line's weight is its pass's power and speed.

Engrave the whole drawing as an image

A PNG the machine sweeps like a printer instead of tracing with the head. The passes become grey values, because in a raster engrave the pixel is the power — the screen palette would put green and cyan at almost the same brightness and two different operations would arrive at the same depth.

—

The image and the SVG are written on the same sheet, same origin, same size, so they line up on the bed: raster the field, then cut the outline without moving the material. The SVG carries only the cut passes — 4 inner and 5 outer.

⚠️ The image cuts nothing, not even the outer cut. Rastered, the line that releases the plate is just a dark line drawn on it — which is why the cut lines go out as vectors beside it. ⚠️ A stroke thinner than about 1.5 pixels does not survive rasterising: it lands as pale grey, and grey here is power, so it is a line the machine barely burns. Thin lines are widened to that floor and the tool says when it happened. ⚠️ A transparent PNG is a real risk at the machine — some laser software composites transparency onto BLACK, which engraves the entire background at full power. Use it for placing the drawing in a document, not for sending to the bed. ⚠️ JPEG is lossy, and its ringing around a line becomes wobble in the burn; PNG is the one to engrave from. ⚠️ The grey ladder is a justified guess until the coupon gives a power and speed for each pass.

Back to QGIS

The drawing as shapefiles in the raster's own coordinates, so the line work can be opened beside the data it came from. One zip: a line layer and, if the drawing has any, a point layer for the circle grid and photo marks. Every record carries the pass it is cut on and the translation that made it, so contours, hachures, sections and the rest can be pulled apart again in QGIS.

⚠️ Closed rings stay polylines. A contour that closes is still a contour; promoting it to a polygon would fill it and imply an area the survey never claimed. ⚠️ Circles leave as points carrying their radius, not as polygons — the circle grid encodes a value as a size, and a frozen polygon throws that value away. ⚠️ A .prj is written only when the raster's CRS can be stated exactly; otherwise QGIS asks once, which is better than this tool guessing a datum.

Properties

Engraved, not cut. Each raster carries its own interval, line style and laser pass, so two surfaces on one sheet can be told apart.

Labels

Each label cuts its own gap first. Upright engraves faster and reads better on material; along-the-line is for drawings meant for paper.

Line style and pass

⚠️ A dash is a real break in a real path, not a linetype: laser software ignores linetypes and would cut the line solid. So a dashed contour is many short marks, and the count is reported before you write the file.

A pass is a machine operation with its own power and speed — choosing a colour here chooses which one the line is cut with, not how it looks on screen.

Hachures

Short strokes down the fall line, hung off this layer's contours and drawn longer where the ground is steeper. The oldest way of showing terrain without tone — and still the grading plan's notation for a cut face or an embankment.

⚠️ Downhill is read from the ground itself, not from which way the contour was traced — a hachure pointing the wrong way turns a hill into a hollow with no other symptom. Every tick is a separate head move, so the count is reported before you export.

Datum
Second material

One threshold turns this layer into patches — everywhere the value exceeds it. Disturbance is the worked example: threshold the difference between two epochs and the patches are the ground that moved.

Overlay is added ground standing proud by its own thickness; window is removed ground, a real void. Two sheets get registration holes cut through both — pin them with dowels before gluing.

Change as circles

The values sampled on a regular grid, each sample a circle whose diameter is the magnitude — a grading plan's read of cut and fill. Point it at the difference between two epochs and the circles are the ground that moved, sized by how much; at the layer's own values for elevation; at its slope for steepness as marks. A raster exported from another tool (a slope or wetness surface) loads as a layer like any other and can be drawn the same way.

⚠️ The difference is drawn, not left to the machine. A circle on the engrave pass looks solid on screen, but what the file carries is an outline — whether it comes out filled depends on that pass being set to raster in JobControl. Hatching puts the distinction in the geometry, where no machine setting can lose it. On material there is no colour to fall back on.

Both sides share one scale — the largest magnitude either way — so equal movement is an equal circle whichever way the ground went, growing from nothing at zero out to full size at the extreme. ⚠️ A hatched circle is many marks, not one; the fill-line count is reported before you export.

Change as hatching

The same values as line density: parallel scanlines that run solid where the value is strong and break into shorter dashes as it weakens. This is the read for a surface with no meaningful contour — a slope raster, a wetness index — where what you want is tone and a laser has no tone but marks.

⚠️ Every dash is a pierce. A run at full density leaves as one continuous path, and a dash under 0.3 mm is dropped rather than burned in place — but the mark count is still the job, and it is reported before you write the file.

Sections

The ground cut open: parallel cuts across the plate, each profile engraved along the line it was taken from. Three cuts put one exactly on the centre line. The profile rides on its own cut because a zero margin leaves nowhere to stack it — and a plate that must tile with its neighbours cannot be resized to make room.

⚠️ The vertical is exaggerated, always, and by a lot at plate scale. The tool computes the true factor from the height you allow and states it in the readout and the cutting report — put it on the drawing.

A phone fixes its position to about 5–10 m. At this scale that is — on the sheet, often larger than the symbol it places. Drag a point on the drawing to correct it against the terrain.

Density by an attribute

⚠️ Inverted on purpose: a high value gives a tighter fill, because density is what a reader sees. Mapped the obvious way round, the densest planting would come out as the emptiest hatch.

Size by an attribute

Pick a numeric column from the .dbf and the symbol grows with it. ⚠️ Scaled by area, not radius: a circle of twice the radius covers four times the paper, so scaling the radius directly makes every large value look several times bigger than it is.

Set From to 0 for true proportionality, where a value of nothing is a symbol of nothing. Otherwise the range is graded between the two sizes.

Turn by an attribute

⚠️ Only the directional symbols show it — turning a circle is a null operation. A field already in degrees (an aspect, a bearing) is used as is, clockwise from north; any other field has no angular meaning, so its range is spread over a full turn and the result is a pattern rather than a direction.

⚠️ A fill is many separate strokes, and every one is a head move. The count is reported before you export. ⚠️ These line styles are the Slicer's own measured run lengths — a dot is 0.4 mm because 0.1 mm burns were invisible on cardboard.
